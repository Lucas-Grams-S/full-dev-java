# J1.14 — `Optional`, records, enums, sealed classes e pattern matching

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J1.06, J1.08, J1.12, J1.13

## 🎯 Objetivos
Ao final desta aula você consegue:
- Usar `Optional` como tipo de retorno para "pode não haver valor" (e saber quando **não** usá-lo).
- Declarar `record` para dados imutáveis, com validação no construtor compacto.
- Usar `enum` com campos e métodos.
- Modelar um conjunto fechado de variantes com `sealed interface` e consumi-lo com `switch` e *pattern matching*.
- Aplicar `instanceof` com *pattern* e *record patterns*.

## 🤔 Por que isso importa
Esses recursos tornam o domínio **expressivo e seguro**: um `Payment` que é *exatamente* Pix, Cartão ou Boleto; um `Money` que não nasce negativo; um `findById` que diz no tipo que pode não achar. São a forma moderna de escrever Java e a que você verá em bases novas.

## 💡 Intuição (explicação simples)
- **`Optional`** é uma **caixa que pode estar vazia**: obriga a abrir e olhar, em vez de devolver "nada" disfarçado de objeto (`null`).
- **`record`** é um **cartão de identificação**: só carrega dados, não muda.
- **`enum`** é o **seletor de um fogão** (desligado, baixo, alto): conjunto fixo de valores.
- **`sealed`** é uma **lista de convidados fechada**: só quem está na lista entra, então o compilador sabe se você tratou todo mundo.

## 🔬 Como funciona por dentro
- **`Optional<T>`:** contêiner imutável com 0 ou 1 valor. `map`, `orElse`, `orElseThrow`, `ifPresent`, `isPresent`.
- **`record R(A a, B b)`:** o compilador gera construtor, acessores (`a()`), `equals`, `hashCode` e `toString` por **todos** os componentes (J1.08). Campos são `final`. O **construtor compacto** valida e normaliza.
- **`enum`:** classe com instâncias fixas; pode ter campos, construtor e métodos; `values()`, `valueOf`, `ordinal`, `name`.
- **`sealed` + `permits`:** só os tipos listados podem implementar/estender. Um `switch` sobre o tipo `sealed` fica **exaustivo** sem `default`: se alguém adicionar uma variante, o compilador acusa todo `switch` que a esqueceu.
- **Pattern matching:** `if (o instanceof Integer i && i > 40)`; e no `switch`: `case Card(String last4, int n) when n > 1 ->` (*record pattern* com guarda `when`).

## 🛠️ Exemplo prático
> Testado com JDK 25 (esses recursos são estáveis desde as versões 16 a 21; ver `versoes.md`).

```java
import java.math.BigDecimal;
import java.util.*;

public class Moderno {
    sealed interface Payment permits Pix, Card, Boleto {}
    record Pix(String key) implements Payment {}
    record Card(String last4, int installments) implements Payment {}
    record Boleto(String barcode) implements Payment {}

    static String describe(Payment p) {
        return switch (p) {                                        // sem default: exaustivo
            case Pix x -> "pix " + x.key();
            case Card(String last4, int n) when n > 1 -> "card " + last4 + " in " + n;
            case Card c -> "card " + c.last4();
            case Boleto b -> "boleto";
        };
    }

    record Money(BigDecimal v) {
        Money {                                                    // construtor compacto
            Objects.requireNonNull(v);
            if (v.signum() < 0) throw new IllegalArgumentException("negative");
        }
    }
    enum Status { PENDING("P"), DONE("D"); final String code; Status(String c) { code = c; } }

    static Optional<String> find(String id) { return id.equals("1") ? Optional.of("Ana") : Optional.empty(); }

    public static void main(String[] args) {
        System.out.println(describe(new Pix("a@b.c")) + "; " + describe(new Card("1234", 3))
            + "; " + describe(new Card("1234", 1)) + "; " + describe(new Boleto("0")));
        System.out.println(new Card("1", 2).equals(new Card("1", 2)) + " " + new Pix("k"));
        try { new Money(new BigDecimal("-1")); } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); }
        System.out.println(Status.valueOf("DONE").code + " " + Arrays.toString(Status.values()) + " " + Status.DONE.ordinal());
        try { Status.valueOf("X"); } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); }
        System.out.println(find("1").map(String::toUpperCase).orElse("?") + find("2").map(String::toUpperCase).orElse("?"));
        try { find("2").orElseThrow(() -> new NoSuchElementException("not found: 2")); }
        catch (NoSuchElementException e) { System.out.println(e.getMessage()); }
        Object o = 42; if (o instanceof Integer i && i > 40) System.out.println("big " + i);
        find("1").ifPresentOrElse(n -> System.out.println("hi " + n), () -> System.out.println("none"));
    }
}
```
Saída real:
```
pix a@b.c; card 1234 in 3; card 1234; boleto
true Pix[key=k]
negative
D [PENDING, DONE] 1
No enum constant Moderno.Status.X
ANA?
not found: 2
big 42
hi Ana
```
Leitura:
- `new Card("1", 2).equals(new Card("1", 2))` é `true` sem você escrever `equals`: igualdade por valor.
- **Ordem dos `case`:** `Card(...) when n > 1` precisa vir **antes** de `case Card c`, senão o compilador acusa código inalcançável.
- Remova `Boleto` do `switch` e o compilador recusa: `the switch expression does not cover all possible input values`.
- **Não persista `ordinal()`** (a ordem pode mudar); grave `name()` ou um código explícito (`code`).

### Aplicando ao `mini-bank`
```java
public record Money(BigDecimal value) implements Comparable<Money> {
    public static final Money ZERO = of("0");
    public Money { value = value.setScale(2, RoundingMode.HALF_EVEN); }   // normaliza
    public static Money of(String text) { return new Money(new BigDecimal(text)); }
    public Money plus(Money o) { return new Money(value.add(o.value)); }
    // ...
}
public enum EntryType { DEPOSIT, WITHDRAWAL }
public record Entry(EntryType type, Money amount, Instant createdAt) {}
// Bank.find devolve Optional<Account>; Bank.get usa orElseThrow
```
Como `Money` normaliza a escala para 2 casas, `Money.of("100")` e `Money.of("100.00")` são **iguais** pelo `equals` do *record* (resolve a armadilha de `BigDecimal` da J1.15). O arredondamento aprofundado vem na J1.15.

## 🧠 Pausa para lógica
**Enunciado:** `Payment` precisa de uma taxa: Pix 0, Cartão 2% (mais 1% por parcela acima de 1), Boleto 3,50 fixo. Escreva `fee(Payment p, BigDecimal amount)` com `switch`.

<details><summary>Dica</summary>Use *record pattern* para ler `installments` de `Card`.</details>
<details><summary>Solução</summary>

```java
static BigDecimal fee(Payment p, BigDecimal amount) {
    return switch (p) {
        case Pix x -> BigDecimal.ZERO;
        case Card(String l, int n) -> amount.multiply(new BigDecimal("0.02").add(
                new BigDecimal("0.01").multiply(BigDecimal.valueOf(Math.max(0, n - 1)))));
        case Boleto b -> new BigDecimal("3.50");
    };
}
```
Se criar `Cash implements Payment` e esquecer de listá-lo, o compilador acusa: o *switch* deixa de ser exaustivo.
</details>

**Variação:** o mesmo problema com herança e `abstract class Fee` (J1.06). O que ficou mais fácil de estender com **uma nova operação**? E com **uma nova variante**?

## ⚠️ Erros comuns e boas práticas de produção
- **`Optional.get()` sem checar** → `NoSuchElementException: No value present`. Prefira `orElse`, `orElseThrow`, `map`.
- **`Optional` em campo, parâmetro ou coleção:** é para **retorno** de método. Em campo/parâmetro, só complica.
- **`Optional.of(null)`** lança NPE; use `ofNullable`.
- **`record` com coleção mutável**: o `record` é raso (*shallow*). Copie com `List.copyOf` no construtor compacto.
- **`record` não é entidade JPA** (J5): JPA exige construtor sem argumentos e campos mutáveis.
- **`enum` persistido por `ordinal`**: reordenar quebra o banco. Persista por nome.
- **`default` em `switch` sobre `sealed`:** desliga a checagem de exaustividade; evite.

<details><summary>Solução de referência (fixação)</summary>

```java
record Point(int x, int y) {
    double distanceTo(Point o) { return Math.hypot(x - o.x, y - o.y); }
}
// new Point(0,0).distanceTo(new Point(3,4)) == 5.0
```

## 🎤 Na entrevista
- **Para que serve `Optional`?** Tornar explícito no tipo de retorno que pode não haver valor, evitando `null`; não deve ser usado em campos nem parâmetros.
- **Record vs classe comum?** Record é um portador imutável de dados que gera construtor, acessores, `equals`, `hashCode` e `toString`.
- **O que ganho com `sealed`?** Hierarquia fechada: o compilador garante exaustividade nos `switch` e seguranças ao evoluir o código.
- **Por que não usar `ordinal()` para persistir um `enum`?** Muda se alguém reordenar as constantes.
