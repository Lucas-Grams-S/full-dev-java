# J1.15 — `java.time`, `BigDecimal` e arquivos (leitura e escrita)

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J1.09, J1.13, J1.14

## 🎯 Objetivos
Ao final desta aula você consegue:
- Escolher entre `Instant`, `LocalDate`, `LocalDateTime` e `ZonedDateTime`, e formatar/ler datas.
- Fazer cálculos monetários com `BigDecimal` (escala, `RoundingMode.HALF_EVEN`, `compareTo`).
- Explicar por que `new BigDecimal(0.1)` e `equals` enganam.
- Ler e escrever arquivos de texto com `java.nio.file` (`Files`, `Path`) e try-with-resources.
- Injetar um `Clock` para tornar o tempo testável.

## 🤔 Por que isso importa
Dinheiro e tempo são os dois domínios em que "quase certo" vira incidente: arredondamento errado em centavos, fuso horário que muda o dia de um vencimento. A decisão do curso é fixa: **dinheiro em `BigDecimal` escala 2 com `HALF_EVEN`** e **timestamps em UTC (`Instant`)** (ver `projeto-central.md`).

## 💡 Intuição (explicação simples)
- **`BigDecimal`** é uma **conta em papel**: cada número carrega suas casas decimais e você decide como arredondar. **`double`** é uma **calculadora científica**: rápida, mas aproximada.
- **`Instant`** é o **relógio atômico** (um ponto na linha do tempo, igual em qualquer lugar); **`ZonedDateTime`** é o **relógio da parede** de uma cidade (hora local com fuso). Guarde o primeiro; mostre o segundo.

## 🔬 Como funciona por dentro
**Tempo (`java.time`)** — todas as classes são **imutáveis**:
| Classe | Representa | Uso |
|---|---|---|
| `Instant` | ponto no tempo (UTC) | timestamps de lançamentos, auditoria |
| `LocalDate` | data sem hora/fuso | vencimento, aniversário |
| `LocalDateTime` | data e hora **sem fuso** | cuidado: ambíguo |
| `ZonedDateTime` | data, hora e fuso | exibir ao usuário |
| `Duration` / `Period` | intervalo em tempo / em datas | prazos |
| `Clock` | fonte de "agora" | injetar em serviços para testar |

**`BigDecimal`** = valor não escalado (inteiro) + **escala** (casas decimais).
- `equals` compara valor **e** escala (`10.00` ≠ `10.0`); use `compareTo` para comparar valor.
- `new BigDecimal(0.1)` herda o erro do `double`; use `new BigDecimal("0.1")` ou `BigDecimal.valueOf(...)`.
- Divisão que não termina (`1/3`) exige escala e modo de arredondamento.
- **`HALF_EVEN`** (arredondamento do banqueiro): no empate (`...5`), arredonda para o dígito par; reduz o viés acumulado em muitas operações. `HALF_UP` sempre sobe no empate.

## 🛠️ Exemplo prático
> Testado com JDK 25 (`java L15.java`). O fuso `America/Sao_Paulo` e as datas são dados do exemplo.

```java
import java.math.*;
import java.nio.file.*;
import java.time.*;
import java.time.format.DateTimeFormatter;
import java.util.*;

public class TempoDinheiroArquivos {
    public static void main(String[] args) throws Exception {
        // --- tempo
        Instant i = Instant.parse("2026-11-12T13:00:00Z");
        System.out.println(i.atZone(ZoneId.of("America/Sao_Paulo")));
        LocalDate d = LocalDate.of(2026, 1, 31);
        System.out.println(d.plusMonths(1) + " " + d.getDayOfWeek() + " " + Duration.ofMinutes(135)
            + " " + Period.between(d, LocalDate.of(2026, 11, 12)));
        DateTimeFormatter br = DateTimeFormatter.ofPattern("dd/MM/yyyy");
        System.out.println(br.format(LocalDate.of(2026, 11, 12)) + " " + LocalDate.parse("12/11/2026", br));

        // --- dinheiro
        System.out.println(new BigDecimal("10.00").equals(new BigDecimal("10.0")) + " "
            + new BigDecimal("10.00").compareTo(new BigDecimal("10.0")));
        System.out.println(new BigDecimal(0.1));
        System.out.println(new BigDecimal("2.345").setScale(2, RoundingMode.HALF_EVEN) + " "
            + new BigDecimal("2.355").setScale(2, RoundingMode.HALF_EVEN) + " "
            + new BigDecimal("2.345").setScale(2, RoundingMode.HALF_UP));
        try { BigDecimal.ONE.divide(new BigDecimal("3")); }
        catch (ArithmeticException e) { System.out.println(e.getMessage()); }
        System.out.println(BigDecimal.ONE.divide(new BigDecimal("3"), 2, RoundingMode.HALF_EVEN));
        BigDecimal fee = new BigDecimal("1000.00").multiply(new BigDecimal("0.015"));
        System.out.println(fee + " " + fee.setScale(2, RoundingMode.HALF_EVEN));

        // --- arquivos
        Path dir = Files.createTempDirectory("mb");
        Path f = dir.resolve("statement.csv");
        Files.write(f, List.of("type,amount", "DEPOSIT,100.00", "WITHDRAWAL,30.25"));
        List<String> lines = Files.readAllLines(f);
        System.out.println(lines.size() + " " + lines.get(1));
        try (var s = Files.lines(f)) {                                  // Stream de linhas: precisa fechar
            System.out.println(s.skip(1).map(l -> l.split(",")[1]).map(BigDecimal::new)
                .reduce(BigDecimal.ZERO, BigDecimal::add));
        }
        Files.writeString(f, "x\n", StandardOpenOption.APPEND);
        System.out.println(Files.readString(f).length());
        try { Files.readString(dir.resolve("nope")); }
        catch (NoSuchFileException e) { System.out.println("NoSuchFile " + e.getMessage().endsWith("nope")); }
    }
}
```

Leitura:
- `31/jan + 1 mês` = `28/fev`: a API ajusta para o último dia válido.
- `2.345 → 2.34` e `2.355 → 2.36` com `HALF_EVEN` (arredonda ao par); `HALF_UP` dá `2.35` para o primeiro.
- `1000.00 × 0.015 = 15.00000` (escalas somadas); normalize com `setScale(2, HALF_EVEN)` ao final de **cada** operação de negócio.
- `Files.lines` devolve um `Stream` ligado ao arquivo: **sempre** em `try-with-resources` (J1.09).
- O tamanho `46` depende do sistema (quebra de linha); não dependa de números assim.

## 🧠 Pausa para lógica (arredondamento de dinheiro)
**Enunciado:** divida R$ 100,00 igualmente entre 3 pessoas **sem perder nem criar centavos**.

<details><summary>Dica</summary>A soma das partes arredondadas pode não fechar R$ 100,00. Distribua o resto.</details>
<details><summary>Solução</summary>

```java
static List<BigDecimal> split(BigDecimal total, int n) {
    BigDecimal base = total.divide(BigDecimal.valueOf(n), 2, RoundingMode.DOWN);   // 33.33
    BigDecimal remainder = total.subtract(base.multiply(BigDecimal.valueOf(n)));    // 0.01
    List<BigDecimal> parts = new ArrayList<>(Collections.nCopies(n, base));
    BigDecimal cent = new BigDecimal("0.01");
    for (int i = 0; remainder.signum() > 0; i++) {                                 // reparte os centavos
        parts.set(i, parts.get(i).add(cent));
        remainder = remainder.subtract(cent);
    }
    return parts;      // [33.34, 33.33, 33.33]  → soma 100.00
}
```
Arredondar cada parte (`33.33 × 3 = 99.99`) perde 1 centavo. É o **problema do resto**, comum em rateios e parcelamentos.
</details>

**Variação:** parcele R$ 100,00 em 6 vezes. Onde fica o centavo extra, na primeira ou na última parcela? Isso é regra de negócio: documente.

## ⚠️ Erros comuns e boas práticas de produção
- **`double` para dinheiro; `new BigDecimal(double)`**.
- **`equals` em `BigDecimal`**: `2.0` e `2.00` não são iguais. Use `compareTo(...) == 0` (ou normalize a escala, como o `Money`).
- **`divide` sem escala**: `ArithmeticException: Non-terminating decimal expansion; no exact representable decimal result.`
- **`LocalDateTime` para guardar momento exato:** sem fuso, a mesma hora significa instantes diferentes; use `Instant`.
- **`new Date()`/`SimpleDateFormat`** (APIs antigas, mutáveis, não *thread-safe*): evite; use `java.time`.
- **Fuso do servidor** implícito: sempre explicite (`ZoneId`) e guarde em UTC.
- **Ler arquivo inteiro** de gigabytes com `readAllLines`: use `Files.lines` (em *stream*) ou `BufferedReader`.
- **Encoding:** `Files.readString`/`writeString` usam UTF-8 por padrão; em APIs antigas (`FileReader`) o padrão depende da plataforma, especifique.
- **Caminhos montados com `+`:** use `Path.resolve`.

## 🎤 Na entrevista
- **Por que `BigDecimal` e não `double`?** `double` é binário e aproximado; `BigDecimal` representa decimais exatos e dá controle de escala e arredondamento.
- **Qual a diferença entre `HALF_UP` e `HALF_EVEN`?** Ambos arredondam o que está acima/abaixo do meio normalmente; no empate `HALF_UP` sobe sempre e `HALF_EVEN` vai para o dígito par, reduzindo o viés acumulado.
- **`Instant` vs `LocalDateTime`?** `Instant` é um momento absoluto; `LocalDateTime` não tem fuso e não identifica um momento. Guarde `Instant`/UTC, converta só para exibir.
