# J1.04 — Arrays e Strings (imutabilidade, `StringBuilder`)

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J1.01 a J1.03

## 🎯 Objetivos
Ao final desta aula você consegue:
- Criar, percorrer, copiar e ordenar arrays (inclusive bidimensionais) com `java.util.Arrays`.
- Explicar por que `String` é imutável e quando usar `StringBuilder`.
- Usar os métodos essenciais de `String` (`split`, `substring`, `strip`, `formatted`, `isBlank`) e *text blocks*.
- Explicar o *string pool* e por que `==` engana.

## 🤔 Por que isso importa
Quase todo dado que entra e sai de um sistema é texto (JSON, CSV, logs, SQL). Concatenar texto em laço sem cuidado derruba desempenho, e um array é a estrutura sobre a qual as listas (J1.10) são construídas.

## 💡 Intuição (explicação simples)
- **Array** é uma **cartela de ovos**: tamanho fixo, posições numeradas a partir de 0, todos do mesmo tipo.
- **String** é uma **placa gravada**: para "mudar", você faz uma placa nova. `StringBuilder` é uma **lousa**: apaga e escreve à vontade, e no fim você tira a foto (`toString()`).

## 🔬 Como funciona por dentro
- Arrays são **objetos** no heap com `length` fixo; elementos recebem valor padrão (`0`, `false`, `null`). Acesso por índice é O(1).
- `String` é **imutável**: métodos como `toUpperCase()` devolvem **outra** `String`. Isso torna-a segura para compartilhar entre *threads* e para ser chave de `Map`.
- **String pool:** literais iguais (`"pay"`) apontam para o mesmo objeto; `new String("pay")` cria outro, fora do pool.
- Concatenar com `+` num laço cria uma nova `String` a cada volta (custo O(n²) no total); `StringBuilder.append` altera um buffer interno.

## 🛠️ Exemplo prático
> Testado com JDK 25 (`java L04.java`).

```java
import java.util.*;

public class ArraysStrings {
    public static void main(String[] args) {
        int[] a = new int[3]; a[0] = 7;
        System.out.println(Arrays.toString(a) + a.length);
        int[][] m = {{1, 2}, {3, 4}};
        System.out.println(Arrays.deepToString(m));
        int[] c = a; c[1] = 5; System.out.println(a[1]);          // mesma referência!
        int[] d = Arrays.copyOf(a, 5); System.out.println(Arrays.toString(d));
        try { a[3] = 1; } catch (ArrayIndexOutOfBoundsException e) { System.out.println(e.getMessage()); }

        String s = "Pay"; s.toUpperCase();                         // resultado descartado
        System.out.println(s + " " + s.toUpperCase());
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 3; i++) sb.append(i).append(',');
        sb.setLength(sb.length() - 1);                             // remove a última vírgula
        System.out.println(sb);
        System.out.println("a,b,,c".split(",").length + " " + String.join("-", "x", "y")
            + " " + "  hi ".strip() + " " + "abc".substring(1, 2) + " " + "abc".indexOf('c'));
        System.out.println("%s tem R$ %.2f".formatted("Ana", 1234.5));
        String tb = """
            {"id": 1,
             "name": "Ana"}
            """;
        System.out.print(tb);
        String x = "pay", y = "pay"; System.out.println(x == y);  // true: mesmo literal no pool
        System.out.println("".isEmpty() + " " + "  ".isBlank());
        Arrays.sort(d); System.out.println(Arrays.toString(d));
    }
}
```
Saída real:
```
[7, 0, 0]3
[[1, 2], [3, 4]]
5
[7, 5, 0, 0, 0]
Index 3 out of bounds for length 3
Pay PAY
0,1,2
4 x-y hi b 2
Ana tem R$ 1234.50
{"id": 1,
 "name": "Ana"}
true
true true
[0, 0, 0, 5, 7]
```
Leitura:
- `int[] c = a` **não copia**: `c` e `a` são o mesmo array (por isso `a[1]` virou 5). Para copiar, `Arrays.copyOf` ou `clone()`.
- `"a,b,,c".split(",")` dá 4 partes (uma vazia no meio).
- `formatted("%.2f")` usa o *locale* padrão da JVM: em máquina configurada como pt-BR sairia `1234,50`. Para saída previsível use `String.format(Locale.US, ...)`.
- *Text block* (`"""`) remove a indentação comum e é ótimo para JSON e SQL.

## 🧠 Pausa para lógica
**Enunciado (duplicidade):** dado um array de ids de transação, diga se há repetidos. Faça primeiro com dois laços (O(n²)). *(Em J1.10 você fará com `Set` em O(n).)*

<details><summary>Dica</summary>Compare cada posição `i` com todas as posições `j > i`.</details>
<details><summary>Solução</summary>

```java
static boolean hasDuplicate(String[] ids) {
    for (int i = 0; i < ids.length; i++)
        for (int j = i + 1; j < ids.length; j++)
            if (ids[i].equals(ids[j])) return true;
    return false;
}
```
</details>

**Variação:** ordene o array primeiro (`Arrays.sort`); como a checagem fica O(n log n)?

## ⚠️ Erros comuns e boas práticas de produção
- **Ignorar o retorno** de métodos de `String` (`s.toUpperCase();` sozinho não faz nada).
- **Comparar `String` com `==`**: use `equals` (ou `equalsIgnoreCase`).
- **Concatenar em laço** com `+=`: use `StringBuilder`. (Concatenações simples fora de laço são otimizadas pelo compilador; não precisa de `StringBuilder` para `a + b`.)
- **Montar SQL com `+`**: abre a porta para SQL injection (J3). Use parâmetros.
- `NullPointerException` ao chamar `texto.trim()` com `texto == null`; `isBlank()` só existe para `String` não nula.
- `java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3`: índice vai de `0` a `length - 1`.

## 🎤 Na entrevista
- **Por que `String` é imutável?** Segurança em *threads*, reuso via *pool*, `hashCode` pode ser guardado em cache, segura como chave de `Map`.
- **`String`, `StringBuilder` e `StringBuffer`?** `StringBuilder` é mutável e não sincronizado (o comum); `StringBuffer` é o equivalente sincronizado (raro hoje).
- **O que é o *string pool*?** Área onde literais iguais compartilham o mesmo objeto.
