# J1.16 — Pacotes, modificadores de acesso, noções de Big-O e JUnit 6 em profundidade

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J1.05, J1.10, J1.11, J1.14, J1.15

## 🎯 Objetivos
Ao final desta aula você consegue:
- Organizar o código em pacotes e aplicar os quatro níveis de acesso.
- Estimar o custo de um algoritmo com Big-O (O(1), O(log n), O(n), O(n log n), O(n²)).
- Escrever testes com JUnit 6 e AssertJ: `@Test`, `@BeforeEach`, `@ParameterizedTest`, `assertThrows`/`assertThatThrownBy`.
- Aplicar o ciclo *Arrange–Act–Assert* e nomear testes pelo comportamento.
- Rodar a suíte com `mvn test` e ler a saída.

## 🤔 Por que isso importa
Teste automatizado é o que permite mudar o código sem medo. Júnior que entrega com testes é revisado mais rápido (J0.05). Big-O é o vocabulário para discutir "essa busca vai aguentar 1 milhão de contas?". Pacotes e modificadores são como você impede que o resto do código dependa do que não devia.

## 💡 Intuição (explicação simples)
- **Pacote** é a **pasta de um armário**: agrupa o que combina. **`private`** é a gaveta com chave; **`public`** é a vitrine.
- **Big-O** é o **tempo de viagem em função da distância**: não importa se o carro anda a 100 ou 120, importa se, dobrando a distância, o tempo dobra (O(n)) ou quadruplica (O(n²)).
- **Teste** é o **ensaio geral**: roda o roteiro antes da estreia, sempre igual.

## 🔬 Como funciona por dentro
**Acesso:**
| Modificador | Visível para |
|---|---|
| `private` | só a própria classe |
| (padrão, sem palavra) | classes do mesmo pacote |
| `protected` | mesmo pacote + subclasses |
| `public` | todos |

Regra prática: comece com o **mais restrito** que funciona. O pacote reflete o domínio (`com.payflow.minibank`); em J5 vira `com.payflow.account`, `com.payflow.transfer`.

**Big-O** (crescimento no pior caso, ignorando constantes):
| Notação | Exemplo no curso |
|---|---|
| O(1) | `HashMap.get`, `array[i]` |
| O(log n) | busca binária, `TreeMap.get` |
| O(n) | percorrer lista, `List.contains` |
| O(n log n) | ordenar (`Arrays.sort`, `List.sort`) |
| O(n²) | dois laços aninhados (duplicidade ingênua) |

**JUnit 6:** a geração atual do JUnit (a documentação oficial, em `docs.junit.org`, mostra a **versão 6.1.3**; exige Java 17+). Usa-se o artefato `org.junit.jupiter:junit-jupiter` (API + engine + parametrizados), executado pelo Maven Surefire. Os pacotes de anotações continuam `org.junit.jupiter.api` (verificado compilando abaixo). **Nota para bases antigas:** projetos em JUnit 5 usam as mesmas anotações e quase o mesmo código; a diferença prática é o número da versão e o requisito de Java. Não confirmamos o *changelog* completo da migração; consulte as notas de release oficiais ao migrar um projeto.

### 2. Teste
`src/test/java/com/payflow/minibank/AccountTest.java`:
```java
package com.payflow.minibank;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import java.time.Clock;
import java.time.Instant;
import java.time.ZoneOffset;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.ValueSource;

class AccountTest {
    private final Clock clock = Clock.fixed(Instant.parse("2026-11-12T10:00:00Z"), ZoneOffset.UTC);
    private Account account;

    @BeforeEach
    void setUp() { account = new Account("acc-1", "Ana", clock); }

    @Test
    void depositIncreasesBalanceAndRecordsEntry() {
        account.deposit(Money.of("100"));                                      // Act
        assertThat(account.balance()).isEqualTo(Money.of("100.00"));           // Assert
        assertThat(account.statement()).hasSize(1);
        assertThat(account.statement().get(0).createdAt())
            .isEqualTo(Instant.parse("2026-11-12T10:00:00Z"));
    }

    @Test
    void withdrawBeyondBalanceFailsAndKeepsBalance() {
        account.deposit(Money.of("50"));
        assertThatThrownBy(() -> account.withdraw(Money.of("50.01")))
            .isInstanceOf(InsufficientFundsException.class)
            .hasMessageContaining("balance=50.00");
        assertThat(account.balance()).isEqualTo(Money.of("50"));
    }

    @ParameterizedTest
    @ValueSource(strings = {"0", "-1", "-0.01"})
    void rejectsNonPositiveAmounts(String amount) {
        assertThatThrownBy(() -> account.deposit(Money.of(amount)))
            .isInstanceOf(IllegalArgumentException.class);
    }

    @Test
    void statementIsReadOnly() {
        account.deposit(Money.of("1"));
        assertThatThrownBy(() -> account.statement().clear())
            .isInstanceOf(UnsupportedOperationException.class);
    }

    @Test
    void moneyRoundsHalfEven() {
        assertThat(Money.of("0.125")).isEqualTo(Money.of("0.12"));
        assertThat(Money.of("0.135")).isEqualTo(Money.of("0.14"));
    }
}
```

### 3. Big-O medido (não só na teoria)
```java
int n = 20_000;
List<Integer> al = new ArrayList<>(); for (int i = 0; i < n; i++) al.add(i);
Set<Integer> hs = new HashSet<>(al);
// n buscas em List.contains (O(n) cada) vs HashSet.contains (O(1))
long t0 = System.nanoTime();
for (int i = 0; i < n; i++) al.contains(n - 1 - i);
long listMs = (System.nanoTime() - t0) / 1_000_000;
t0 = System.nanoTime();
for (int i = 0; i < n; i++) hs.contains(n - 1 - i);
long setMs = (System.nanoTime() - t0) / 1_000_000;
```
No ambiente de teste, `listMs > setMs` foi `true` (a diferença de ordem de grandeza é grande). **Os milissegundos exatos variam por máquina e por aquecimento da JVM**; para medir de verdade use JMH (P1/S2). Aqui o objetivo é ver a curva, não o número.

Busca binária (O(log n)) em array **ordenado**: `Arrays.binarySearch(new int[]{1,3,5,7,9,11}, 7)` devolve `3`; para ausente, devolve `-(ponto de inserção) - 1`: `binarySearch(..., 4)` dá `-3`. Um índice de banco (J3) é a versão persistente dessa ideia.

## 🧠 Pausa para lógica
**Enunciado:** qual a complexidade de `hasDuplicate` com dois laços, com `Set` e com ordenação prévia? Se `n` passa de 1.000 para 1.000.000 (×1000), quantas vezes mais lento cada uma fica, em ordem de grandeza?

<details><summary>Dica</summary>O(n²) cresce ao quadrado do fator; O(n) linearmente; O(n log n) um pouco mais que linear.</details>
<details><summary>Solução</summary>

Dois laços O(n²): ×1.000.000 (um milhão de vezes). `Set` O(n): ×1.000. Ordenar O(n log n): ≈ ×1.500 (1000 × log(10⁶)/log(10³) = 1000 × 2). É por isso que "funciona na minha máquina com 100 contas" não garante nada em produção.
</details>

**Variação:** em um extrato de 50 milhões de linhas, por que `SELECT ... WHERE account_id = ?` sem índice é O(n) e com índice B-tree é O(log n)? *(Estudo em J3.)*

## ⚠️ Erros comuns e boas práticas de produção
- **Tudo `public`**: vaza detalhes. Reduza a visibilidade; só exponha o contrato.
- **Pacote por camada gigante** (`controllers`, `services`) em projeto pequeno: prefira agrupar por domínio (`account`, `transfer`); a discussão aprofunda em P4.
- **Teste que depende de `Instant.now()`**, de ordem de execução ou de arquivo na máquina: flaky. Injete `Clock`; use `@TempDir` do JUnit para arquivos temporários.
- **Teste sem assertiva** (só chama o método): passa sempre.
- **Nome ruim** (`test1`): nomeie pelo comportamento (`withdrawBeyondBalanceFailsAndKeepsBalance`).
- **Um teste verificando dez coisas**: quando falha, não se sabe o quê.
- **Surefire antigo** não encontra os testes e a saída mostra `Tests run: 0`: confira a versão do plugin no `pom.xml`.
- **Maven compilando com Java antigo**: `error: release version 25 not supported` → `JAVA_HOME` apontando para JDK menor que 25 (J0.02).
- **Big-O sem medir:** a notação ignora constantes; para `n` pequeno, O(n²) simples pode ganhar de O(n log n) complexo.

## 🎤 Na entrevista
- **Qual a diferença entre `private`, padrão, `protected` e `public`?** Classe; pacote; pacote + subclasses; todos.
- **O que é O(n log n) e onde aparece?** Algoritmos de ordenação eficientes (`Arrays.sort`, `List.sort`).
- **Como você testaria uma classe que usa a hora atual?** Injetando um `Clock` (fixo no teste), em vez de chamar `Instant.now()` direto.
- **Teste de unidade vs integração?** Unidade isola uma classe sem I/O; integração usa componentes reais (banco, rede). A pirâmide vem em J7.
