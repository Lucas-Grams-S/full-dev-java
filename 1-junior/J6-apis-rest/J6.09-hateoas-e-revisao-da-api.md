## 🎯 Objetivos
Ao final desta aula você consegue:
- Explicar **HATEOAS** e o **modelo de maturidade de Richardson**, e dizer em que nível está a API do PayFlow.
- Justificar por que o PayFlow **não** adota hipermídia completa agora.

## 🤔 Por que isso importa
"Isso é REST de verdade?" é pergunta clássica de entrevista e de revisão de código. Saber **onde** a sua API está nessa escala, e por quê, mostra maturidade; saber **quando não** investir em hipermídia também.

## 💡 Intuição (explicação simples)
Em um site, você não decora URLs: clica em **links** que a página oferece. HATEOAS (*Hypermedia As The Engine Of Application State*) é fazer a **API** oferecer os links do que se pode fazer a seguir ("esta transferência pode ser `cancel`ada"), em vez de o cliente montar URLs de cabeça.

## 🔬 Como funciona por dentro
Modelo de Richardson ([artigo de Martin Fowler](https://martinfowler.com/articles/richardsonMaturityModel.html)):

| Nível | O que é | PayFlow |
|---|---|---|
| 0 | Um endpoint, tudo por `POST` (RPC) | não |
| 1 | **Recursos** com URIs próprias | sim |
| 2 | Verbos HTTP e **status** com semântica | **sim (onde estamos)** |
| 3 | **Hipermídia** (links na resposta) | só parcial: `Location` no 201, `hasNext` na lista |

Hipermídia completa usa um formato (HAL, JSON:API...) e exige clientes que **sigam links**. O Spring tem o projeto Spring HATEOAS, que **não usamos**. Decisão: nível 2, com `Location` e paginação explícita. Motivo: clientes do PayFlow (painel e integrações simples) conhecem o contrato via OpenAPI (J6.07); o custo de formato, biblioteca e clientes "inteligentes" não se paga agora.

## 🛠️ Exemplo prático
### 1. Revisão da API (checklist)
- [ ] Todo caminho é substantivo no plural sob `/api/v1`; verbos HTTP corretos.
- [ ] Status certo (201+`Location`, 400/401/404/405/409/415/422/502/504); nenhum `200` com erro.
- [ ] Todo erro é `application/problem+json`; `type` estável; nada de internals.
- [ ] Dinheiro em string com 2 casas; datas ISO-8601 UTC; ids UUID; entidade nunca no JSON.
- [ ] Listas com `size` limitado, ordem com desempate, `hasNext`.
- [ ] `POST /transfers` exige `Idempotency-Key`, escopo por usuário, corrida resolvida.
- [ ] Spec OpenAPI válida (teste), documentação **desligada em produção**.
- [ ] CORS só para origens configuradas; `Location` exposto.
- [ ] Chamadas externas com timeout e erros traduzidos.
- [ ] Endpoint legado do painel (`/api/accounts/{id}/statement`) **mantido** sem versão: migrar o `statement.js` para `/api/v1/accounts/{id}/entries` é evolução (contrato do painel, decisão 22).

### 2. Script de fumaça
`scripts/api-smoke.sh` (jq e curl): faz login e confere 15 cenários; sai com código ≠ 0 se algum falhar:
```bash
#!/usr/bin/env bash
# Fumaça da API REST do PayFlow (J6): login, leitura, depósito, transferência, idempotência e erros.
# Uso: scripts/api-smoke.sh [URL_BASE]      (a aplicação precisa estar rodando com o perfil dev)
set -u
BASE="${1:-http://localhost:8080}"
JAR="$(mktemp)"
ANA_1=20000000-0000-0000-0000-000000000001
ANA_2=20000000-0000-0000-0000-000000000004
BRUNO=20000000-0000-0000-0000-000000000002
FAILED=0

check() {   # check "descrição" status_esperado status_real
  if [ "$2" = "$3" ]; then echo "ok    $1 ($3)"; else echo "FALHA $1: esperado $2, veio $3"; FAILED=1; fi
}
status() { curl -s -o /dev/null -w '%{http_code}' -b "$JAR" "$@"; }
json()   { curl -s -b "$JAR" "$@"; }

curl -s -o /dev/null -c "$JAR" -d 'email=ana@payflow.dev' "$BASE/login"

check "sem sessão -> 401"            401 "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/api/v1/accounts")"
check "listar contas"                200 "$(status "$BASE/api/v1/accounts")"
check "conta de outro usuário"       404 "$(status "$BASE/api/v1/accounts/$BRUNO")"
check "id que não é UUID"            404 "$(status "$BASE/api/v1/accounts/abc")"
check "extrato com filtro"           200 "$(status "$BASE/api/v1/accounts/$ANA_1/entries?type=CREDIT&size=2")"
check "extrato com size inválido"    400 "$(status "$BASE/api/v1/accounts/$ANA_1/entries?size=500")"

check "depósito"                     201 "$(status -H 'Content-Type: application/json' -d '{"amount":"10.00"}' "$BASE/api/v1/accounts/$ANA_2/deposits")"
check "depósito com 3 casas"         400 "$(status -H 'Content-Type: application/json' -d '{"amount":"10.001"}' "$BASE/api/v1/accounts/$ANA_2/deposits")"

KEY="smoke-$(date +%s)-$RANDOM"
BODY="{\"sourceAccountId\":\"$ANA_1\",\"targetAccountId\":\"$BRUNO\",\"amount\":\"1.00\"}"
check "transferência"                201 "$(status -H 'Content-Type: application/json' -H "Idempotency-Key: $KEY" -d "$BODY" "$BASE/api/v1/transfers")"
check "repetição da mesma chave"     200 "$(status -H 'Content-Type: application/json' -H "Idempotency-Key: $KEY" -d "$BODY" "$BASE/api/v1/transfers")"
check "mesma chave, outro valor"     422 "$(status -H 'Content-Type: application/json' -H "Idempotency-Key: $KEY" -d "${BODY/1.00/2.00}" "$BASE/api/v1/transfers")"
check "sem Idempotency-Key"          400 "$(status -H 'Content-Type: application/json' -d "$BODY" "$BASE/api/v1/transfers")"
check "saldo insuficiente"           422 "$(status -H 'Content-Type: application/json' -H "Idempotency-Key: $KEY-x" -d "${BODY/1.00/99999999.00}" "$BASE/api/v1/transfers")"
check "rota inexistente"             404 "$(status "$BASE/api/v1/nope")"
check "método errado"                405 "$(status -X DELETE "$BASE/api/v1/accounts")"

echo "--- erro de exemplo (Problem Details):"
json -H 'Content-Type: application/json' -H "Idempotency-Key: $KEY-y" -d "${BODY/1.00/99999999.00}" "$BASE/api/v1/transfers" | jq .
rm -f "$JAR"
exit $FAILED
```

Execução real contra a aplicação no perfil `dev`:
```text

ok    listar contas (200)
ok    conta de outro usuário (404)
ok    id que não é UUID (404)
ok    extrato com filtro (200)
ok    extrato com size inválido (400)
ok    depósito (201)
ok    depósito com 3 casas (400)
ok    transferência (201)
ok    repetição da mesma chave (200)
ok    mesma chave, outro valor (422)
ok    sem Idempotency-Key (400)
ok    saldo insuficiente (422)
ok    rota inexistente (404)
ok    método errado (405)
```
e, ao final, imprime um Problem Details de exemplo (saldo insuficiente, `422`).

## 🧠 Pausa para lógica
**Enunciado:** dado um conjunto de respostas de uma API, classifique em qual nível de Richardson ela está. Resposta A: `POST /api` com `{"op":"getAccount"}`; B: `GET /accounts/1` devolvendo 200 ou 404; C: `GET /accounts/1` devolvendo `{"balance":"10.00","links":{"deposit":"/accounts/1/deposits"}}`.
<details><summary>Solução</summary>A = 0; B = 2 (recurso + verbo + status); C = 3 (hipermídia). (Raciocínio, não executado.)</details>

## ⚖️ Trade-offs e quando NÃO usar
Hipermídia ajuda quando clientes e servidor evoluem separadamente e há fluxos com estado (links condicionais por estado). Em APIs internas pequenas, o custo supera o ganho.

## ⚠️ Erros comuns e boas práticas de produção
Chamar de "REST" qualquer JSON; adotar HAL sem cliente que use; misturar versões de formato; esquecer de revisar o contrato antes de publicar.
