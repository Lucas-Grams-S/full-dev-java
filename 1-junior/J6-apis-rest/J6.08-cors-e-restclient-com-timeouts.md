# J6.08 — CORS e consumo de APIs externas com `RestClient` (timeouts)

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J4.05 (mesma origem e CORS no navegador), J2.04 (cookies e `SameSite`), J5.05 (`@ConfigurationProperties`), J6.04 (erros)

## 🎯 Objetivos
Ao final desta aula você consegue:
- Explicar **origem**, a política de **mesma origem**, o **preflight** e os cabeçalhos `Access-Control-*`.
- Configurar o **CORS** da API para origens explícitas, com cookie (`allowCredentials`), e provar com um **navegador real**.
- Consumir uma API externa com **`RestClient`** configurando **timeouts**, e traduzir as falhas dela em `502`/`504`/`422`.
- Testar o cliente contra um **servidor HTTP falso** (lento, quebrado, fora do ar).

## 🤔 Por que isso importa
Dois problemas do dia a dia: (1) o front-end em outra porta "não consegue chamar a API" (erro de CORS no console) e a "solução" copiada da internet é `allowedOrigins("*")`, que **abre a API a qualquer site**; (2) a primeira integração com uma API de terceiros **sem timeout**: quando ela fica lenta, **as suas threads ficam penduradas** e a sua aplicação cai junto.

## 💡 Intuição (explicação simples)
**CORS:** o porteiro do prédio B só deixa o morador do prédio A entrar se o **síndico de B** tiver deixado o nome de A numa lista. Quem decide é o **navegador** (o porteiro do cliente), seguindo a lista que **o servidor** publica. **Timeout:** ao ligar para um serviço externo, você define **quanto tempo espera** antes de desligar; sem isso, fica no telefone para sempre.

## 🔬 Como funciona por dentro
- **Origem** = esquema + host + porta. `http://localhost:5173` e `http://localhost:8080` são origens **diferentes**. Já o **site** (para o `SameSite` do cookie) ignora a porta: os dois são o mesmo site, então o cookie `SameSite=Lax` do PayFlow **é enviado** (testado abaixo).
- **Preflight**: antes de um `POST` com JSON ou cabeçalho customizado (`Idempotency-Key`), o navegador manda um `OPTIONS` perguntando "posso?". O servidor responde com `Access-Control-Allow-Origin`, `-Methods`, `-Headers`, `-Credentials` e `-Max-Age`. **O preflight nunca leva cookie.**
- `allowCredentials(true)` exige **origem explícita** (nunca `*`).
- `exposedHeaders("Location")`: sem isso o JavaScript **não consegue ler** o `Location` da resposta.
- **CORS não é segurança do servidor**: um `curl` ignora. Protege o **navegador do usuário**. Autorização continua sendo J8.

## 🛠️ Exemplo prático
### 1. CORS
Propriedade `payflow.cors.allowed-origins` (lista; vazia por padrão = sem CORS) e a configuração:
```java
package com.payflow.web;

import com.payflow.config.PayflowProperties;
import java.util.regex.Pattern;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.ApiVersionConfigurer;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    private static final Pattern VERSIONED_PATH = Pattern.compile("^/api/v(\\d+)/");

    private final AuthInterceptor authInterceptor;
    private final PayflowProperties properties;

    public WebConfig(AuthInterceptor authInterceptor, PayflowProperties properties) {
        this.authInterceptor = authInterceptor;
        this.properties = properties;
    }

    /**
     * Versão da API no caminho: /api/v1/... -> "1". Só valem para /api/vN/; páginas e o endpoint legado do
     * painel (/api/accounts/...) não têm versão (o resolvedor devolve null) e seguem como antes.
     */
    @Override
    public void configureApiVersioning(ApiVersionConfigurer configurer) {
        configurer.usePathSegment(1, path -> VERSIONED_PATH.matcher(path.value()).find())
                .addSupportedVersions("v1").setVersionRequired(false);
    }

    /**
     * CORS só para a API e só para as origens configuradas (payflow.cors.allowed-origins). O cookie de sessão
     * só vai em chamadas entre sites com allowCredentials(true) E uma origem explícita (nunca "*").
     */
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        var origins = properties.cors().allowedOrigins();
        if (origins.isEmpty()) {
            return;                                                  // sem origens configuradas, sem CORS
        }
        registry.addMapping("/api/v1/**")
                .allowedOrigins(origins.toArray(String[]::new))
                .allowedMethods("GET", "POST")
                .allowedHeaders("Content-Type", "Idempotency-Key")
                .exposedHeaders("Location")
                .allowCredentials(true)
                .maxAge(3600);
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(authInterceptor).addPathPatterns("/accounts/**", "/api/**");
    }
}
```

**Armadilha real:** com o `AuthInterceptor` cobrindo `/api/**`, o preflight (sem cookie) recebia **401**, e o navegador recusa preflight não-2xx. O interceptor agora deixa passar `CorsUtils.isPreFlightRequest(request)`.

### 2. `RestClient` com timeouts
Spring Boot 4.1: `spring-boot-starter-restclient` (traz o módulo `spring-boot-http-client`) e as propriedades do PayFlow (`payflow.exchange.base-url`, `connect-timeout`, `read-timeout`); o Boot também tem propriedades globais `spring.http.clients.connect-timeout`/`read-timeout` (lidas no metadado do módulo; **não** testadas aqui).

Laboratório sem Spring (o que acontece com e sem timeout):
```java
package com.payflow.api;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import com.payflow.support.ExchangeStub;
import java.time.Duration;
import org.junit.jupiter.api.Test;
import org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder;
import org.springframework.boot.http.client.HttpClientSettings;
import org.springframework.web.client.ResourceAccessException;
import org.springframework.web.client.RestClient;

/** Laboratório (sem Spring): o que acontece com e sem timeout. */
class RestClientTimeoutLabTest {

    @Test
    void withoutTimeoutTheCallerWaitsForTheSlowServer() throws Exception {
        try (var stub = new ExchangeStub()) {
            stub.delayMillis = 2500;
            var client = RestClient.builder().baseUrl(stub.url()).build();               // nenhum timeout configurado
            long t0 = System.nanoTime();
            String body = client.get().uri("/v1/latest").retrieve().body(String.class);
            long ms = (System.nanoTime() - t0) / 1_000_000;
            System.out.println("LAB sem timeout: respondeu depois de " + ms + " ms");
            assertThat(body).isNotBlank();
            assertThat(ms).isGreaterThanOrEqualTo(2500);
        }
    }

    @Test
    void withReadTimeoutTheCallFailsFast() throws Exception {
        try (var stub = new ExchangeStub()) {
            stub.delayMillis = 2500;
            var settings = HttpClientSettings.defaults().withTimeouts(Duration.ofMillis(300), Duration.ofMillis(500));
            var client = RestClient.builder().baseUrl(stub.url())
                    .requestFactory(ClientHttpRequestFactoryBuilder.jdk().build(settings)).build();
            long t0 = System.nanoTime();
            assertThatThrownBy(() -> client.get().uri("/v1/latest").retrieve().body(String.class))
                    .isInstanceOf(ResourceAccessException.class)
                    .satisfies(e -> System.out.println("LAB com timeout: " + e.getClass().getSimpleName()
                            + " causa=" + e.getCause().getClass().getName() + " msg=" + e.getMessage()));
            long ms = (System.nanoTime() - t0) / 1_000_000;
            System.out.println("LAB com timeout: falhou em " + ms + " ms");
            assertThat(ms).isLessThan(1500);
        }
    }

    @Test
    void connectionRefusedFailsImmediately() {
        var client = RestClient.builder().baseUrl("http://127.0.0.1:1").build();         // porta 1: ninguém escuta
        assertThatThrownBy(() -> client.get().uri("/x").retrieve().body(String.class))
                .isInstanceOf(ResourceAccessException.class)
                .satisfies(e -> System.out.println("LAB recusada: " + e.getMessage() + " | causa=" + e.getCause()));
    }
}
```

O cliente do PayFlow para a API pública Frankfurter ([frankfurter.dev](https://frankfurter.dev/)):
```java
package com.payflow.client;

import com.payflow.config.PayflowProperties;
import java.math.BigDecimal;
import java.net.SocketTimeoutException;
import java.net.http.HttpTimeoutException;
import java.time.LocalDate;
import java.util.Map;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder;
import org.springframework.boot.http.client.HttpClientSettings;
import org.springframework.stereotype.Component;
import org.springframework.web.client.HttpClientErrorException;
import org.springframework.web.client.ResourceAccessException;
import org.springframework.web.client.RestClient;
import org.springframework.web.client.RestClientException;

/** Cliente da API pública Frankfurter (https://frankfurter.dev): GET /v1/latest?base=USD&symbols=BRL. */
@Component
public class FrankfurterExchangeRates implements ExchangeRates {

    private static final Logger log = LoggerFactory.getLogger(FrankfurterExchangeRates.class);

    /** O formato da resposta externa: só os campos que usamos (o resto é ignorado). */
    record LatestResponse(String base, LocalDate date, Map<String, BigDecimal> rates) { }

    private final RestClient client;

    public FrankfurterExchangeRates(PayflowProperties properties) {
        var exchange = properties.exchange();
        var settings = HttpClientSettings.defaults()
                .withTimeouts(exchange.connectTimeout(), exchange.readTimeout());     // SEMPRE: o padrão é esperar para sempre
        this.client = RestClient.builder()
                .baseUrl(exchange.baseUrl())
                .requestFactory(ClientHttpRequestFactoryBuilder.jdk().build(settings))
                .defaultHeader("Accept", "application/json")
                .build();
    }

    @Override
    public ExchangeRate rate(String base, String quote) {
        try {
            LatestResponse body = client.get()
                    .uri("/v1/latest?base={base}&symbols={quote}", base, quote)
                    .retrieve()
                    .body(LatestResponse.class);
            BigDecimal rate = body == null || body.rates() == null ? null : body.rates().get(quote);
            if (rate == null || rate.signum() <= 0) {
                throw new ExchangeRateUnavailableException("Exchange API returned no rate for " + base + "/" + quote, false, null);
            }
            return new ExchangeRate(base, quote, rate, body.date());
        } catch (ResourceAccessException e) {                       // rede: recusou, caiu, demorou
            boolean timeout = isTimeout(e);
            log.warn("Exchange API unreachable: timeout={} cause={}", timeout, e.getMostSpecificCause().getClass().getSimpleName());
            throw new ExchangeRateUnavailableException("Exchange API unreachable", timeout, e);
        } catch (HttpClientErrorException.NotFound e) {             // 404: a moeda não existe na API
            throw new UnsupportedCurrencyException(quote);
        } catch (RestClientException e) {                           // outros 4xx/5xx da API externa ou corpo ilegível
            log.warn("Exchange API failed: {}", e.getClass().getSimpleName());
            throw new ExchangeRateUnavailableException("Exchange API failed", false, e);
        }
    }

    private static boolean isTimeout(Throwable e) {
        for (Throwable t = e; t != null; t = t.getCause()) {
            if (t instanceof HttpTimeoutException || t instanceof SocketTimeoutException) {
                return true;
            }
        }
        return false;
    }
}
```

Tradução das falhas (no `ApiErrors`, J6.04): **timeout** → `504 Gateway Timeout`; **API quebrada/resposta inválida** → `502 Bad Gateway`; **moeda inexistente** → `422`. O corpo do erro **não** repassa o texto da API externa.

O servidor falso é HTTP de verdade (JDK `HttpServer` com um *pool* de threads: com uma thread só, uma resposta lenta travaria as outras e o teste mentiria):
```java
package com.payflow.support;

import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;
import java.util.concurrent.atomic.AtomicInteger;

/** API de câmbio de mentira (JDK HttpServer): dá para escolher resposta, status e atraso. Não é um mock: é HTTP de verdade. */
public class ExchangeStub implements AutoCloseable {

    private final HttpServer server;
    public volatile int status = 200;
    public volatile long delayMillis = 0;
    public volatile String body = "{\"amount\":1.0,\"base\":\"BRL\",\"date\":\"2026-11-13\",\"rates\":{\"USD\":0.1765}}";
    public final AtomicInteger calls = new AtomicInteger();

    public ExchangeStub() throws IOException {
        server = HttpServer.create(new InetSocketAddress("127.0.0.1", 0), 0);
        server.createContext("/", exchange -> {
            calls.incrementAndGet();
            try {
                Thread.sleep(delayMillis);
                byte[] bytes = body.getBytes(StandardCharsets.UTF_8);
                exchange.getResponseHeaders().add("Content-Type", "application/json");
                exchange.sendResponseHeaders(status, bytes.length);
                exchange.getResponseBody().write(bytes);
            } catch (IOException | InterruptedException ignored) {
                // cliente desistiu (timeout): normal neste laboratório
            } finally {
                exchange.close();
            }
        });
        server.setExecutor(java.util.concurrent.Executors.newCachedThreadPool());   // um atendimento lento não pode travar os outros
        server.start();
    }

    public String url() {
        return "http://127.0.0.1:" + server.getAddress().getPort();
    }

    public void reset() {
        status = 200;
        delayMillis = 0;
        calls.set(0);
        body = "{\"amount\":1.0,\"base\":\"BRL\",\"date\":\"2026-11-13\",\"rates\":{\"USD\":0.1765}}";
    }

    @Override
    public void close() {
        server.stop(0);
    }
}
```

## 🧠 Pausa para lógica
**Enunciado:** se a API externa responde em 3 s e o seu *pool* tem 200 threads, quantos pedidos por segundo você sustenta **sem** timeout nem cache? E com timeout de 500 ms?
<details><summary>Solução</summary>Lei de Little: vazão ≈ threads ÷ tempo de atendimento. Sem timeout: 200 ÷ 3 ≈ 67 pedidos/s e, se a API travar, 0. Com timeout de 500 ms o pior caso é 200 ÷ 0,5 = 400 pedidos/s (falhando rápido) e as threads **voltam** ao pool. (Raciocínio, não medido.)</details>

## ⚖️ Trade-offs e quando NÃO usar
Chamar API externa **dentro** da requisição acopla sua latência à dela; para dados que mudam pouco, **cache** (P3) ou chamada assíncrona. `RestClient` é síncrono; para muitos chamados concorrentes, avaliar `WebClient`/threads virtuais (P1/P3).

## ⚠️ Erros comuns e boas práticas de produção
- `allowedOrigins("*")` com cookies (o navegador recusa) ou sem querer abrir a API.
- Esquecer de expor `Location`.
- **Sem timeout** (padrão: esperar indefinidamente).
- Repassar o erro da API externa ao cliente.
- Retentar sem limite nem *backoff*.
- Chamar a API externa em teste automatizado (flakiness): use servidor falso.

## 🎤 Na entrevista
- **O que é CORS?** Mecanismo do navegador que, por cabeçalhos do servidor, relaxa a política de mesma origem.
- **O que é um preflight?** `OPTIONS` automático antes de requisições "não simples".
- **Por que definir timeouts?** Para não prender threads em dependências lentas e falhar rápido.
