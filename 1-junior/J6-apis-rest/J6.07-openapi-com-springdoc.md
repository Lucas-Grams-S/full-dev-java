# J6.07 — OpenAPI com springdoc

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J6.01 a J6.06, J5.05 (perfis e propriedades)

> ✅ **Validação final (2026-11-24):** este módulo foi executado no PayFlow reconstruído; o resultado e o que continua não executado estão no [README do módulo](README.md). Os avisos "não executado" / "por leitura" abaixo descrevem a escrita original.

## 🎯 Objetivos
Ao final desta aula você consegue:
- Explicar o que é **OpenAPI** (o contrato legível por máquina) e o que o **Swagger UI** faz com ele.
- Gerar a documentação da API do PayFlow com **springdoc-openapi** e enriquecê-la com anotações (`@Tag`, `@Operation`, `@ApiResponse`, `@Schema`).
- **Validar** a especificação gerada em um teste e **desligá-la em produção**.
- Evitar as cinco armadilhas que apareceram ao gerar esta documentação.

## 🤔 Por que isso importa
Documentação escrita à mão **desatualiza**. Uma especificação **gerada do código** e **validada em teste** é um contrato vivo: gera clientes, alimenta testes de contrato e deixa o time de front-end trabalhar sem perguntar "qual é o formato?".

## 💡 Intuição (explicação simples)
O **cardápio impresso** que sai automaticamente da cozinha: se o prato muda, o cardápio muda no mesmo dia. OpenAPI é o cardápio em formato que um computador lê; Swagger UI é o cardápio bonito para humanos, com botão "experimentar".

## 🔬 Como funciona por dentro
- **OpenAPI** (antes "Swagger") é uma especificação de contrato HTTP (JSON/YAML): caminhos, parâmetros, corpos, respostas, esquemas de segurança. O PayFlow gera a versão **3.1.0**.
- **springdoc-openapi** lê seus controllers e DTOs (mapeamentos, tipos, Bean Validation) e publica `/v3/api-docs` e a UI em `/swagger-ui/index.html`. Versão **3.2.0**, compatível com Spring Boot 4.1 (o POM dele declara 4.1.2); **não** está no BOM do Boot, por isso é declarada (`springdoc.version`).
- Anotações **complementam** o que o código não diz (resumo, descrição, exemplos, respostas de erro). O resto sai da inferência.

## 🛠️ Exemplo prático
Dependência (`springdoc-openapi-starter-webmvc-ui`) e propriedades:
```yaml
# application.yml (base = produção): documentação desligada
springdoc:
  api-docs:
    enabled: false
  swagger-ui:
    enabled: false
  paths-to-match: /api/v1/**

# application-dev.yml e application-test.yml
springdoc:
  api-docs:
    enabled: true
  swagger-ui:
    enabled: true
```
Metadados globais e o esquema de segurança (cookie de sessão, provisório até a J8):
```java
package com.payflow.config;

import io.swagger.v3.oas.models.Components;
import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.security.SecurityRequirement;
import io.swagger.v3.oas.models.security.SecurityScheme;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/** Metadados globais da documentação OpenAPI da API do PayFlow. */
@Configuration
public class OpenApiConfig {

    static final String SESSION_SCHEME = "sessionCookie";

    @Bean
    OpenAPI payflowOpenApi(PayflowProperties properties) {
        return new OpenAPI()
                .info(new Info().title("PayFlow API").version("1.0.0")
                        .description("API REST do PayFlow: contas, depósitos, extrato e transferências. "
                                + "Dinheiro trafega como string com 2 casas (\"110.00\"); datas em ISO-8601 UTC; "
                                + "erros em Problem Details (RFC 9457)."))
                .components(new Components().addSecuritySchemes(SESSION_SCHEME, new SecurityScheme()
                        .type(SecurityScheme.Type.APIKEY).in(SecurityScheme.In.COOKIE)
                        .name(properties.session().cookieName())
                        .description("Sessão provisória (cookie), criada por POST /login. Substituída na J8.")))
                .addSecurityItem(new SecurityRequirement().addList(SESSION_SCHEME));
    }
}
```

package com.payflow.web.api.dto;

import io.swagger.v3.oas.annotations.media.Schema;
import java.util.List;

/** Só para a documentação: o formato dos erros (RFC 9457). A resposta real é um ProblemDetail do Spring. */
@Schema(name = "Problem", description = "Problem Details (RFC 9457), application/problem+json")
public record ProblemBody(
        @Schema(example = "urn:payflow:problem:insufficient-funds",
                description = "Identifica o TIPO do erro; é o que o cliente deve testar (não o texto)") String type,
        @Schema(example = "Insufficient funds") String title,
        @Schema(example = "422") int status,
        @Schema(example = "The source account does not have enough balance for this transfer.") String detail,
        @Schema(example = "/api/v1/transfers") String instance,
        @Schema(description = "Só nos erros de validação (400): um item por campo inválido") List<FieldError> errors) {

    public record FieldError(@Schema(example = "amount") String field,
                             @Schema(example = "deve ser maior que 0") String message) { }
}

Controller documentado (a versão final do `TransfersController`):
```java
package com.payflow.web.api;

import com.payflow.domain.NotFoundException;
import com.payflow.service.TransferOutcome;
import com.payflow.service.TransferService;
import com.payflow.service.TransferSubmitter;
import com.payflow.web.AuthInterceptor;
import com.payflow.web.CurrentUser;
import com.payflow.web.api.dto.CreateTransferRequest;
import com.payflow.web.api.dto.TransferResponse;
import com.payflow.web.api.dto.ProblemBody;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.validation.Valid;
import java.net.URI;
import java.util.UUID;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestAttribute;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestHeader;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@Tag(name = "Transfers", description = "Transferências entre contas (atômicas e idempotentes)")
@RestController
@RequestMapping(path = "/api/v1/transfers", version = "v1", produces = "application/json")
public class TransfersController {

    private final TransferSubmitter submitter;
    private final TransferService transfers;
    private final ApiMapper mapper;

    public TransfersController(TransferSubmitter submitter, TransferService transfers, ApiMapper mapper) {
        this.submitter = submitter;
        this.transfers = transfers;
        this.mapper = mapper;
    }

    @Operation(operationId = "createTransfer", summary = "Transfere dinheiro entre contas",
            description = "Débito, crédito e lançamentos numa única transação. Exige o cabeçalho Idempotency-Key: "
                    + "repetir a mesma chave com o mesmo corpo devolve a mesma transferência (200).")
    @ApiResponse(responseCode = "201", description = "Transferência criada")
    @ApiResponse(responseCode = "200", description = "Chave já usada com o mesmo corpo: a transferência original")
    @ApiResponse(responseCode = "400", description = "Corpo inválido ou Idempotency-Key ausente", content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemBody.class)))
    @ApiResponse(responseCode = "409", description = "Conflito de concorrência: tente de novo", content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemBody.class)))
    @ApiResponse(responseCode = "422", description = "Regra de negócio: saldo insuficiente, conta indisponível, origem = destino, chave reutilizada com outro corpo", content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemBody.class)))
    @PostMapping
    public ResponseEntity<TransferResponse> create(@Parameter(hidden = true) @RequestAttribute(AuthInterceptor.USER) CurrentUser user,
                                                   @Parameter(description = "Chave escolhida pelo cliente (até 63 caracteres), única por pedido", example = "7c9e6679-7425-40de-944b-e07fc1f90ae7")
                                                   @RequestHeader("Idempotency-Key") String idempotencyKey,
                                                   @Valid @RequestBody CreateTransferRequest request) {
        TransferOutcome outcome = submitter.submit(user.id(), request.sourceAccountId(), request.targetAccountId(),
                request.amount(), IdempotencyKeys.normalize(idempotencyKey));
        URI location = URI.create("/api/v1/transfers/" + outcome.transfer().getId());
        TransferResponse body = mapper.toResponse(outcome.transfer());
        // Primeira vez: 201 Created. Repetição da mesma chave: 200 OK com a MESMA transferência.
        return outcome.replayed() ? ResponseEntity.ok().location(location).body(body)
                : ResponseEntity.status(HttpStatus.CREATED).location(location).body(body);
    }

    @Operation(operationId = "getTransfer", summary = "Detalha uma transferência", description = "Visível para o dono da origem e o do destino.")
    @ApiResponse(responseCode = "200", description = "Transferência encontrada")
    @ApiResponse(responseCode = "404", description = "Inexistente ou de terceiros", content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemBody.class)))
    @GetMapping("/{id}")
    public TransferResponse get(@Parameter(hidden = true) @RequestAttribute(AuthInterceptor.USER) CurrentUser user, @PathVariable UUID id) {
        return transfers.findVisibleTo(user.id(), id).map(mapper::toResponse)
                .orElseThrow(() -> new NotFoundException("Transfer not found: " + id));
    }
}
```

**Armadilhas reais** (cada uma foi vista e corrigida ao gerar o contrato):
```text
1) version = "1" com segmento v1  -> paths no OpenAPI: /api/1/transfers ... (errado)   | com version = "v1" -> /api/v1/transfers (certo)
2) só @ApiResponse de erro (400, 404) em um GET -> o 200 SOME da documentação e o schema PageResponse desaparece
   corrigido com @ApiResponse(responseCode = "200", description = "...") (o springdoc preenche o corpo pelo tipo de retorno)
3) sem produces = "application/json" as respostas de sucesso saíam como */*
4) sem operationId explícito o springdoc gerou "create" para o POST de transferências
5) springdoc.paths-to-match: /api/v1/** evita documentar as páginas do painel
```

**Teste do contrato** (valida a especificação com o `swagger-parser` e confere o que importa; dependência de teste `io.swagger.parser.v3:swagger-parser:2.1.48`):
```java
package com.payflow.api;

import static org.assertj.core.api.Assertions.assertThat;

import com.payflow.support.ApiClient;
import java.nio.file.Files;
import java.nio.file.Path;
import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.web.server.LocalServerPort;
import org.springframework.test.context.ActiveProfiles;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@ActiveProfiles("test")
class OpenApiTest {

    @LocalServerPort int port;

    @Test
    void specIsValidAndDocumentsTheContract() throws Exception {
        var r = new ApiClient(port).get("/v3/api-docs");
        assertThat(r.statusCode()).isEqualTo(200);
        Files.writeString(Path.of(System.getProperty("openapi.out", "target/openapi.json")), r.body());
        var result = new io.swagger.v3.parser.OpenAPIV3Parser().readContents(r.body(), null, null);
        assertThat(result.getMessages()).isEmpty();
        var api = result.getOpenAPI();
        assertThat(api.getPaths().keySet()).contains("/api/v1/transfers", "/api/v1/accounts/{id}/entries");
        assertThat(api.getPaths().get("/api/v1/transfers").getPost().getResponses().keySet())
                .contains("201", "200", "400", "409", "422");
        var ui = new ApiClient(port).get("/swagger-ui/index.html");
    }
}
```

## ⚖️ Trade-offs e quando NÃO usar
Anotações demais poluem o controller (use meta-anotações ou *customizers*); documentação **só** inferida é pobre. Nunca exponha a UI em produção sem decidir (revela a superfície da API).

## ⚠️ Erros comuns e boas práticas de produção
Documentar o painel junto com a API; exemplos que não batem com a regra; esquecer de documentar os erros (`Problem`); UI aberta em produção.
