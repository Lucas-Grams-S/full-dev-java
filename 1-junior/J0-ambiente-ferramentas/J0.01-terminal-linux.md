# J0.01 — Terminal Linux/WSL, sistema de arquivos e permissões

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: nenhum

## 🎯 Objetivos
Ao final desta aula você consegue:
- Navegar e manipular arquivos e pastas só pelo terminal (`pwd`, `cd`, `ls`, `mkdir`, `cp`, `mv`, `rm`).
- Ler e alterar permissões (`rwx`, `chmod`) e explicar o que `-rwxr-xr--` significa.
- Combinar comandos com pipe (`|`) e redirecionamento (`>`, `>>`).
- Usar variáveis de ambiente e entender o `PATH`.
- Procurar texto e arquivos com `grep` e `find`.

## 🤔 Por que isso importa
Servidores, containers, pipelines de CI e a nuvem não têm interface gráfica. Todo dev lê logs, procura arquivos, ajusta permissões e roda comandos no terminal. Um júnior que domina o básico perde menos tempo em tarefas simples e erra menos ao mexer em ambientes reais.

## 💡 Intuição (explicação simples)
O terminal é **pedir as coisas por escrito** em vez de apontar com o dedo. Na interface gráfica você clica na pasta; no terminal você diz "entre na pasta X". Parece mais lento no começo, mas **o que está escrito pode ser repetido, automatizado e compartilhado**: um script é uma receita, um clique não.

O sistema de arquivos é um **prédio de arquivos**: a raiz (`/`) é a portaria, cada pasta é um andar ou sala, e o caminho (`/home/lucas/docs`) é o endereço completo.

## 🔬 Como funciona por dentro

**Shell.** O terminal é só a janela; quem interpreta o que você digita é o *shell* (aqui, `bash`). Ele separa o texto em palavras, procura o programa pelo nome nas pastas listadas em `PATH` e o executa.

```mermaid
flowchart LR
    T[Você digita: ls -l /tmp] --> S[bash separa em palavras]
    S --> P{Procura 'ls' nas pastas do PATH}
    P --> E[/bin/ls executa com args '-l' '/tmp']
    E --> O[Saída no terminal]
```

**Caminhos.** *Absoluto* começa em `/` (`/home/lucas`). *Relativo* parte da pasta atual (`../docs`). `.` é a pasta atual, `..` a pasta pai, `~` a sua home.

**Estrutura típica no Linux:** `/home` (usuários), `/etc` (configuração), `/var/log` (logs), `/tmp` (temporários), `/usr/bin` (programas).

**Permissões.** Cada arquivo tem dono, grupo e três blocos de permissão: dono, grupo, outros.

```
-rwxr-xr--  1 lucas dev  120 nov 12 run.sh
│└┬┘└┬┘└┬┘
│ │  │  └─ outros: só leitura (r--)
│ │  └──── grupo: ler e executar (r-x)
│ └─────── dono: ler, escrever e executar (rwx)
└───────── tipo: - arquivo, d diretório, l link
```

`r`=4, `w`=2, `x`=1. `rwx`=7, `r-x`=5, `r--`=4, então `-rwxr-xr--` é `754`. Em diretórios, `x` significa "poder entrar".

**Pipe e redirecionamento.** Todo programa tem entrada padrão (stdin), saída padrão (stdout) e saída de erro (stderr). `|` liga o stdout de um ao stdin do próximo. `>` grava a saída em arquivo (sobrescreve), `>>` acrescenta, `2>` redireciona erros.

**Variáveis de ambiente.** Pares nome=valor herdados pelos programas que você inicia. `PATH` e, mais adiante, `JAVA_HOME` são as mais importantes.

## 🛠️ Exemplo prático

> No Windows, abra o **WSL2 com Ubuntu** e trabalhe dentro dele (veja `00-guia/setup-ambiente.md`). Tudo abaixo roda em Linux e no WSL.

Crie uma área de treino (não mexe em nada seu):

```bash
mkdir -p ~/treino-j0/logs && cd ~/treino-j0
pwd                      # /home/<seu-usuario>/treino-j0
```

Criar, copiar, mover, apagar:

```bash
echo "transfer ok" > logs/app.log          # cria o arquivo
echo "transfer FAILED: saldo insuficiente" >> logs/app.log   # acrescenta
cp logs/app.log logs/app.bak               # copia
mv logs/app.bak /tmp/app.bak               # move
rm /tmp/app.bak                            # apaga (não há lixeira!)
ls -l logs                                 # lista com detalhes
```

Ver conteúdo e procurar texto:

```bash
cat logs/app.log
grep -n "FAILED" logs/app.log              # 2:transfer FAILED: saldo insuficiente
grep -ri "saldo" .                         # busca recursiva
find . -name "*.log"                       # ./logs/app.log
wc -l logs/app.log                         # 2 logs/app.log
```

Pipe:

```bash
cat logs/app.log | grep FAILED | wc -l     # 1
```

Permissões:

```bash
printf '#!/usr/bin/env bash\necho "olá do script"\n' > hello.sh
./hello.sh                                 # bash: ./hello.sh: Permissão negada
ls -l hello.sh                             # -rw-rw-r-- ... (sem x)
chmod +x hello.sh
./hello.sh                                 # olá do script
chmod 754 hello.sh && ls -l hello.sh       # -rwxr-xr-- ...
```

Variáveis e PATH:

```bash
export PAYFLOW_ENV=dev
echo $PAYFLOW_ENV                          # dev
echo $PATH | tr ':' '\n' | head -3         # uma pasta por linha
which java                                 # onde o 'java' é encontrado
```

Uma variável com `export` só vale no terminal atual e nos programas que ele inicia. Para valer sempre, vai em `~/.bashrc`.

Comandos úteis para o dia a dia: `history`, `Ctrl+R` (busca no histórico), `Tab` (autocompletar), `Ctrl+C` (interrompe), `man ls` ou `ls --help` (ajuda), `less arquivo` (navegar em arquivo grande, `q` sai), `tail -f arquivo` (acompanhar log ao vivo).

## 🧠 Pausa para lógica
Você tem um `app.log` com milhares de linhas no formato `2026-11-12T10:01:03Z INFO transfer id=123 ok` ou `... ERROR transfer id=124 failed`. **Enunciado:** descreva, em linguagem natural, como contar quantas transferências falharam. Depois escreva o comando.

<details><summary>Dica</summary>Divida em passos pequenos: filtrar linhas, depois contar. Cada passo é um programa; o pipe liga os dois.</details>

<details><summary>Solução</summary>

```bash
grep "ERROR transfer" app.log | wc -l
# ou, em um só programa:
grep -c "ERROR transfer" app.log
```
Pensar em "filtrar → transformar → agregar" é a mesma lógica dos Streams que você verá em J1.13.
</details>

**Variação mais difícil:** liste os 5 `id=` que mais aparecem entre os erros. *(Dica: `grep -o`, `sort`, `uniq -c`, `sort -rn`, `head`.)*

## ⚠️ Erros comuns e boas práticas de produção
| Mensagem | Causa | Correção |
|---|---|---|
| `bash: ./hello.sh: Permissão negada` (em inglês: `Permission denied`) | Arquivo sem `x` | `chmod +x hello.sh` |
| `bash: foo: comando não encontrado` | Programa fora do `PATH` ou não instalado | Conferir o nome, `which foo`, instalar |
| `ls: não foi possível acessar 'x': Arquivo ou diretório inexistente` | Caminho errado | `pwd` e `ls` para se localizar |

- **`rm -rf` não tem lixeira.** Antes de apagar, rode o mesmo comando com `ls` para ver o que será afetado. Nunca use `rm -rf` com variável que pode estar vazia (`rm -rf $DIR/`).
- **Não use `sudo` por reflexo.** Se precisou de `sudo` para uma tarefa de desenvolvimento, pergunte por quê.
- **Não use `chmod 777`.** Dá permissão a todos; quase sempre existe uma solução mais estreita.
- Nunca coloque senhas ou tokens em comandos digitados: ficam no `history`.

## 🎤 Na entrevista
- **O que `chmod 644 arquivo` faz?** Dono lê e escreve; grupo e outros só leem. É o padrão para arquivos de texto.
- **Qual a diferença entre `>` e `>>`?** `>` sobrescreve o arquivo; `>>` acrescenta ao final.
- **Como você acompanha um log em tempo real e filtra erros?** `tail -f app.log | grep ERROR`.
