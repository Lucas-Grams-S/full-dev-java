# J4.03 — CSS: grid e responsividade

> ⏱️ ~1h30 · 🟢 Júnior · Pré-requisitos: J4.02 (CSS: box model e flexbox)

## 🎯 Objetivos
Ao final desta aula você consegue:
- Montar um layout em **linhas e colunas** com **CSS Grid** (`grid-template-columns`, `fr`, `repeat`, `minmax`, `gap`).
- Fazer a mesma página funcionar em tela larga e em celular com **`<meta name="viewport">`**, **media queries** e a abordagem **mobile-first**.
- Criar uma grade que **se adapta sozinha** (`repeat(auto-fill, minmax(...))`) sem escrever uma media query.
- Deixar a tabela do extrato rolar **dentro** da própria caixa em telas estreitas, sem rolagem horizontal da página.
- Verificar o resultado em diferentes larguras com o **modo dispositivo** do DevTools.

## 🤔 Por que isso importa
Hoje, boa parte dos usuários de um sistema financeiro está no celular. Uma tela que só funciona em monitor largo é um defeito, não um detalhe. Para o dev Java, o que importa é saber **ler** e **corrigir** CSS responsivo ("a tabela estoura no iPhone"), e entender por que o servidor devolve o **mesmo HTML** para todos: quem se adapta ao tamanho da tela é o CSS, no navegador.

## 💡 Intuição (explicação simples)
Se o flexbox é uma **prateleira** (uma fileira), o grid é um **quadro de avisos quadriculado**: você desenha linhas e colunas e cada cartão ocupa suas células. **Responsividade** é um **quadro que muda de tamanho**: em um mural grande, os cartões ficam lado a lado; em um quadrinho de geladeira, empilham. Você não escreve três páginas; escreve **regras** do tipo "cada cartão tem no mínimo 16rem; coloque quantos couberem".

## 🔬 Como funciona por dentro

### 1. O viewport do celular
Sem a tag abaixo, o celular finge ter uma tela de ~980 px de largura e **encolhe** a página inteira. Com ela, a largura do layout é a da tela real:
```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```
(Já está nas páginas desde a J4.01.)

### 2. CSS Grid
`display: grid` cria um **contêiner grid**; as colunas são declaradas no contêiner e os filhos diretos ocupam as células, em ordem.

| Propriedade | Efeito |
|---|---|
| `grid-template-columns: 2fr 1fr` | duas colunas; a primeira com **o dobro** do espaço livre (`fr` = fração do que sobra) |
| `repeat(3, 1fr)` | três colunas iguais |
| `minmax(16rem, 1fr)` | cada coluna tem **pelo menos** 16rem e **no máximo** uma fração |
| `repeat(auto-fill, minmax(16rem, 1fr))` | **quantas colunas couberem**, cada uma com ≥ 16rem |
| `gap` | espaço entre linhas e colunas |
| `grid-column: span 2` | o item ocupa 2 colunas |

**Flex × Grid:** flex distribui ao longo de **um eixo** e o conteúdo manda no tamanho; grid define a **estrutura de duas dimensões** e o contêiner manda. Na prática se combinam: grid para a página e para a lista de cartões; flex dentro de cada componente.

### 3. Media queries e mobile-first
```css
/* base = celular (uma coluna) */
.layout { display: grid; gap: 1rem; grid-template-columns: 1fr; }

/* a partir de 48rem (≈768 px), duas colunas */
@media (min-width: 48rem) {
  .layout { grid-template-columns: 2fr 1fr; }
}
```
**Mobile-first**: escreva primeiro o estilo para a tela pequena (mais simples) e use `min-width` para **acrescentar** em telas maiores. Dá menos código e menos sobrescrita que o contrário. Pontos de quebra em `rem`/`em` acompanham o zoom do usuário. Outras consultas úteis: `prefers-color-scheme: dark`, `prefers-reduced-motion: reduce` (acessibilidade, J4.08).

### 4. Medindo (no Chrome 156, `docs/frontend-lab/03-grid-responsivo.html`)
O laboratório tem `.cards` com `repeat(auto-fill, minmax(16rem, 1fr))` (4 cartões) e `.layout` com a media query acima. Abrimos a mesma página em três larguras e lemos `grid-template-columns` calculado:

| Largura da janela | Cartões em… | `.layout` em… | Rolagem horizontal? |
|---|---|---|---|
| 1200 px | **4** colunas | 2 colunas | não |
| 700 px | **2** colunas | 1 coluna | não |
| 390 px | **1** coluna | 1 coluna | não |

Nenhuma media query foi usada nos cartões: o `auto-fill` fez as contas. (Com 700 px, o `.layout` ainda está em 1 coluna porque 700 px < 48rem = 768 px.)

### 5. Tabelas em tela estreita
Uma tabela não "quebra" sozinha. A solução mais simples e robusta é envolvê-la em um contêiner com **rolagem própria**:
```css
.table-wrap { overflow-x: auto; }   /* a tabela rola DENTRO da caixa; a página não */
```
Com poucas colunas (data, descrição, valor), a tabela do extrato coube em 390 px sem precisar rolar, porque as células quebram linha; o `white-space: nowrap` só vai na coluna de valor, para o número não partir.

## 🛠️ Exemplo prático
Segunda metade do `web-prototype/app.css` (junte à da J4.02):

```css
.container { width: min(100% - 2rem, 60rem); margin-inline: auto; padding-block: 1.5rem; }
.container.narrow { max-width: 28rem; }

.site-footer { padding: 1rem; text-align: center; color: var(--muted); font-size: .875rem; }

/* cartões: grid que se adapta à largura */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(16rem, 1fr));
  gap: var(--gap);
  list-style: none;
  margin: 1rem 0 0;
  padding: 0;
}
.card, .panel {
  background: var(--surface);
  border: 1px solid var(--border);
  border-radius: var(--radius);
  padding: 1rem;
}
.panel h2:first-child { margin-top: 0; }
.card-title { margin: 0; font-size: 1rem; color: var(--muted); }
.balance { font-size: 1.5rem; font-weight: 700; margin: .25rem 0; }

.badge { display: inline-block; padding: .125rem .5rem; border-radius: 999px; font-size: .8125rem; border: 1px solid currentColor; }
.badge-ok { color: var(--ok); }
.badge-warn { color: var(--warn); }

.button-secondary { background: transparent; color: var(--brand); }
.button-secondary:hover { background: var(--brand); color: #fff; }
.button-quiet { background: transparent; color: var(--text); border-color: var(--border); }
.button-quiet:hover { background: var(--bg); border-color: var(--muted); color: var(--text); }

/* tabela do extrato */
.table-wrap { overflow-x: auto; background: var(--surface); border: 1px solid var(--border); border-radius: var(--radius); }
table { width: 100%; border-collapse: collapse; }
th, td { padding: .5rem .75rem; text-align: left; border-bottom: 1px solid var(--border); }
tbody tr:last-child td { border-bottom: 0; }
.num { text-align: right; font-variant-numeric: tabular-nums; white-space: nowrap; }
.credit { color: var(--ok); }
.debit { color: var(--danger); }
.pager { display: flex; justify-content: space-between; gap: var(--gap); }

@media (min-width: 48rem) {
  .container { padding-block: 2rem; }
}
```
`min(100% - 2rem, 60rem)` limita o conteúdo a 60rem **e** garante 1rem de folga de cada lado em telas pequenas, sem media query. `margin-inline: auto` centraliza.

**Passo a passo:**
1. Cole as duas metades em `web-prototype/app.css`.
2. Dê `class="container"` ao `main`, `class="cards"` à lista de contas e `class="card"` a cada item; `class="table-wrap"` à `div` em volta da tabela e `class="num"` às células de valor.
3. Abra a página, aperte **F12** → ícone de **modo dispositivo** (*Toggle device toolbar*) e teste 390, 768 e 1200 px.
4. A aba **Elements** mostra uma etiqueta "grid" ao lado do contêiner: clique para ver as linhas da grade desenhadas sobre a página.

Resultado (capturado no Chrome 156, 390 px de largura): cabeçalho com marca à esquerda e usuário/"Sair" à direita; saldo em destaque; formulário em um cartão; tabela com 3 colunas sem rolagem horizontal; rodapé embaixo. Em 1100 px, o conteúdo fica centrado em ~60rem.

## 🧠 Pausa para lógica
O `.cards` usa `repeat(auto-fill, minmax(16rem, 1fr))`. Em uma janela de 1000 px de largura (conteúdo com `min(100% - 2rem, 60rem)` = 960 px) e `gap: 1rem` (16 px), **quantas colunas** o navegador cria? E o que muda se trocar `auto-fill` por `auto-fit` quando há só **2** cartões?

<details><summary>Dica e solução</summary>

Dica: 16rem = 256 px (rem = 16px); a conta é `n × 256 + (n − 1) × 16 ≤ 960`. Solução: n = 3 → 768 + 32 = 800 ✔; n = 4 → 1024 + 48 = 1072 > 960 ✘; logo **3 colunas**. Com 2 cartões, `auto-fill` **mantém as colunas vazias**: medimos 3 colunas de ≈309 px e os 2 cartões com 309 px cada; `auto-fit` **colapsa** a coluna vazia (`472px 472px 0px`) e os 2 cartões se esticam para 472 px cada, ocupando a linha toda. Com 5 cartões os dois dão 3 colunas (testado no Chrome 156).
</details>

## ⚠️ Erros comuns e boas práticas de produção
- **Esquecer o `<meta viewport>`:** o celular mostra a versão "desktop" miniaturizada e nenhuma media query de largura parece funcionar.
- **Largura fixa em `px`** (`width: 960px`): rolagem horizontal no celular. Use `max-width` e porcentagens.
- **Media query "desktop-first" cheia de `max-width`:** vira uma pilha de sobrescritas. Prefira mobile-first com `min-width`.
- **Pontos de quebra por aparelho** ("iPhone", "iPad"): aparelhos mudam; quebre onde **o conteúdo** quebra.
- **Rolagem horizontal da página:** quase sempre um elemento com largura fixa ou `100vw` + barra de rolagem. No console: `document.documentElement.scrollWidth > innerWidth` mostra se existe.
- **Imagens sem `max-width: 100%`:** estouram o contêiner.
- **Testar só no DevTools:** o modo dispositivo simula largura, não o desempenho nem o teclado do celular; teste em um aparelho real antes de entregar algo importante.

<details><summary>Soluções de referência</summary>

1. (a) Duas colunas; a primeira recebe o dobro do espaço livre da segunda. (b) Cada coluna tem **no mínimo** 16rem e **no máximo** uma fração do espaço, permitindo adaptar o número de colunas. (c) Escrever o estilo base para telas pequenas e **acrescentar** regras em telas maiores com `min-width`; menos sobrescrita. (d) Envolver a tabela em um contêiner com `overflow-x: auto` (e deixar as células quebrarem linha).
3. Contêiner em `grid` com `grid-template-columns: 1fr;` e, em `@media (min-width: 64rem) { ...{ grid-template-columns: 1fr 2fr; align-items: start; } }`. Como o formulário vem antes da tabela no HTML, ele fica em cima no celular e à esquerda no desktop.
</details>

## 🎤 Na entrevista
- **Quando usar Grid e quando usar Flexbox?** Flexbox para distribuir itens em **uma** dimensão (barras, grupos de botões); Grid para layouts em **duas** (a página, uma galeria de cartões). Muitas vezes os dois juntos.
- **O que é design responsivo e como você faz?** A mesma página se adapta à largura: `viewport`, unidades relativas, grades fluidas (`auto-fill/minmax`), media queries mobile-first e imagens flexíveis.
- **Para que serve `<meta name="viewport">`?** Faz a largura do layout ser a da tela do dispositivo, em vez da largura "virtual" de ~980 px que o celular usaria.
- **Como você testa responsividade?** DevTools (modo dispositivo, várias larguras), verificação de rolagem horizontal e teste em dispositivos reais.
